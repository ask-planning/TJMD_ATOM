### ID を暫定にしている理由

SVF 共有に権限のあるアカウントを**カスタムアカウントに指定しようとしたが、
「指定したパスワードは無効です」で登録できなかった。**
そのアカウントが**別サーバーのローカルアカウント**で、新サーバー側では検証できないためと見られる（推測）。

**SVF への書き込みは後回しにして、先にアプリを動かす方針とした。**
今日の主目的（Windows Server 2025 で ASP.NET 4.8.1 が動くか）はこれで達成できる。

対応は `/Pages/Report/SvfConnectionTest.aspx` で実行アカウントを確認してから決める（§8-1）。

### 作業ログ

- `C:\inetpub` へ書き込むと UAC の確認が出る。ログイン中のアカウントは `BUILTIN\Administrators` に所属しているため、**「続行」を押すだけで通る**
- ZIP で持ち込んだ場合は、**展開する前に** ZIP の「プロパティ」→「許可する」にチェックしてブロックを解除すること（展開後では中のファイルに効かない）
- 2026-10-23 配置先を `C:\inetpub\atom` から **D ドライブ配下** へ変更。今後ほかのシステムも同じサーバーに載せる想定
- 2026-10-23 いったん種類別（`D:\WebApps` / `D:\WebData` / `D:\IISLogs` / `D:\Deploy` の下にシステム名）で作成したが、お客様から「既存踏襲でなくてよいので、システム毎の階層化を」との要望があり、**システムを最上位に置く構成（§5-1）に変更**した
- IIS マネージャーは**管理者として実行**すること
- フォルダのセキュリティで `IIS AppPool\AtomAppPool` を追加するとき、「場所」の既定がドメイン（`*.local`）になっている。**一覧の一番上のコンピューター名（このサーバー）に切り替える**こと。ドメインのままだと名前が見つからない
- 継承を切ったため、匿名認証の既定ユーザー（`IUSR`）には権限が無い。**サイトの「認証」→「匿名認証」→「編集」で「アプリケーション プール ID」に変更**した（忘れると CSS・画像だけ表示されない）
- このサーバーはドメインに参加している可能性がある（推測）。その場合 §8-1 の SVF 共有は、ドメインアカウントを ID にすれば通る可能性がある。要確認

## 1. 前提

| 項目 | 内容 |
|---|---|
| OS | Windows Server 2025 |
| Web サーバー | IIS |
| ランタイム | **.NET Framework 4.8.1**（OS に同梱） |
| 認証 | **独自のログイン画面**（社員コード）。Windows 認証は使わない |
| セッション | `InProc`（アプリケーションプールの再起動でログインが切れる） |
| 必要な権限 | 対象サーバーの管理者権限 |

> ATOM は Windows 認証を使いません（`Web.config` の `authentication mode="None"`）。
> そのため IIS 側で特別な認証設定は不要で、**匿名認証のまま**で動きます。

## 2. 【重要】配置前に必ず行うこと

### 2-1. 接続文字列を外に出す

> **【2026-10-21 現在：暫定で平文のまま進めています】**
> 接続先が**検証用 DB** であることを踏まえ、今回の配置では本項を適用していません。
> **次の条件のいずれかに当てはまる前に、必ず対応すること。**
>
> - 接続先を**本番 DB** に変えるとき
> - サーバーを**社内の他の利用者に公開**するとき
> - **本番運用を始める**とき


`src/Atom.Web/Web.config` に**接続文字列が平文で入っています**（SQL Server の認証情報を含む）。
このままサーバーへ置かないでください。

対応は次のどれかです。

| 案 | 内容 |
|---|---|
| **A** | **Windows 統合認証に変える**（`Integrated Security=True`）。アプリケーションプールの ID に DB 権限を与える。**推奨** |
| B | `connectionStrings` を別ファイルへ出し（`configSource`）、そのファイルはリポジトリに含めない |
| C | `aspnet_regiis -pe` で `connectionStrings` セクションを暗号化する |

**いずれにせよ、サーバー上の `Web.config` には平文のパスワードを置かないでください。**
リポジトリの `Web.config` からも実値を外し、空のひな形に戻すこと。

> 本書で接続文字列を記載するときは `Password=***` のようにマスクしてください。

### 2-2. デバッグを切る

`Web.config` の `compilation` を、検証でも本番でも `debug="false"` にします。

```xml
<compilation debug="false" strict="true" explicit="true" targetFramework="4.8.1" />
```

`true` のままだと遅くなり、エラーの詳細が外に出ます。

## 5. サーバーへ配置する

1. 配置先フォルダを用意する（§5-1 の構成。ATOM は `D:\Systems\ATOM\app`）
2. 発行物を ZIP で持ち込む場合は、`D:\Systems\ATOM\deploy` に置き、**展開する前に**ブロックを解除する（ZIP の「プロパティ」→「許可する」）
3. 展開した発行物の中身を `D:\Systems\ATOM\app` にすべてコピーする
4. **`Web.config` をこの環境用に書き換える**（§6）

### 5-1. D ドライブのフォルダ構成（2026-10-23 決定）

**このサーバーには今後ほかのシステムも載せる想定です。**
お客様の要望（システム毎の階層化）に合わせ、**システムを最上位に置き、そのシステムのものはすべてその下にまとめます。**
システムごとにフォルダ・アプリケーションプール・サイトを 1 組ずつ作り、互いに影響しないようにします。

```
D:\
├ Systems\                  ← 全システムの置き場（ここで権限継承を切る）
│  ├ ATOM\                  ← ATOM のものはすべてこの下
│  │  ├ app\                  稼働中のプログラム（IIS の物理パス）
│  │  ├ logs\                 アプリのログ（Web.config の Log.FolderPath）
│  │  ├ iislogs\              IIS のアクセスログ（サイト単位で指定。§9-1）
│  │  │  └ FailedReq\           失敗した要求のトレース（使うときだけ）
│  │  ├ backup\
│  │  │  └ 20261023_01\       差し替え前の app を退避（戻すときに使う）
│  │  └ deploy\               持ち込んだ発行物（ZIP）の受け場所
│  └ （別システム）\
│     └ （ATOM と同じ構成）
└ ServerLogs\
   └ IIS\                   ← サーバー共通の IIS ログ（ここで権限継承を切る）
      └ Sites\                出力先を指定していないサイトのアクセスログの受け皿
```

| ルール | 理由 |
|---|---|
| **システムを最上位に置き、そのシステムのものは全部その下に置く** | 1 フォルダで全体が見える。撤去・移設・バックアップがシステム単位で済む |
| システム単位でフォルダ・アプリケーションプール・サイトを 1 組ずつ作る | 1 つのシステムの不具合や再起動が他に波及しない。権限も分けられる |
| `app` は読み取り専用。書き込むのは `logs` だけ | プログラムのフォルダに書き込み権限を付けずに済む（§8） |
| 差し替え前の `app` を `backup\yyyyMMdd_連番` に退避する | 失敗してもフォルダを戻すだけで元に戻せる |
| サーバー共通のものは `ServerLogs` に分ける | システムのフォルダに、どのシステムのものでもないファイルを混ぜない |
| ログはすべて D に置く | ログが増えても C ドライブを圧迫しない |
| フォルダ名は英字で、空白を入れない | PowerShell の引用符のトラブルを避ける |

#### システムを追加するとき

1. `D:\Systems\（システム名）\` に、ATOM と同じ `app` / `logs` / `iislogs` / `backup` / `deploy` を作る
2. そのシステム専用のアプリケーションプールを作る（§7）
3. `app` に「読み取りと実行」、`logs` に「変更」を、**そのシステムのアプリケーションプールにだけ**付ける（§8）
4. サイトを作り、ログの出力先をそのシステムの `iislogs` にする（§9・§9-1）
5. 下の台帳に追記する

#### 差し替えの手順

1. IIS マネージャーでサイト `ATOM` を停止する
2. `D:\Systems\ATOM\app` の中身を `D:\Systems\ATOM\backup\yyyyMMdd_連番\` へ移す
3. 新しい発行物を `app` にコピーする（`Web.config` は退避したものを戻す）
4. サイトを開始して §11 を確認する

> **戻すとき**はサイトを停止し、`app` の中身を退避フォルダのものと入れ替える。

#### 着手前の確認

- [x] **D ドライブが一時ディスクでないこと。**（2026-10-23 確認済み）
- [ ] **`D:\Systems` と `D:\ServerLogs` の権限継承を切ること。** C 以外のドライブのルートは、既定で `Authenticated Users` に「変更」が付いていることが多い（推測。`icacls D:\` で確認）。継承を無効にし、`Administrators` と `SYSTEM` だけを残したうえで、各アプリケーションプールの ID を個別に追加する（§8）

#### サイト・ポートの台帳

システムを追加したら、ここに追記してください。

| システム | サイト名 | アプリケーションプール | 物理パス | ポート |
|---|---|---|---|---:|
| ATOM | `ATOM` | `AtomAppPool` | `D:\Systems\ATOM\app` | 8080 |

> システムが増えたら、ポートではなく**ホスト名で分ける**ことも検討する（例 `atom.（社内ドメイン）`。DNS 登録が必要）。

### 5-2. 種類別の構成から組み替える（2026-10-23 時点で一度だけ行う作業）

いったん作った種類別の構成（`D:\WebApps` / `D:\WebData` / `D:\IISLogs` / `D:\Deploy`）を、§5-1 の構成に移します。

1. IIS マネージャーでサイト `ATOM` を停止する
2. `D:\Systems` と `D:\ServerLogs` を作り、**権限継承を切る**（§5-1「着手前の確認」）
3. `D:\Systems\ATOM\` の下に `app` / `logs` / `iislogs` / `backup` / `deploy` を、`D:\ServerLogs\IIS\` の下に `Sites` を作る
4. `D:\WebApps\ATOM\app` の中身を `D:\Systems\ATOM\app` へ移す
5. `app` と `logs` に `IIS AppPool\AtomAppPool` の権限を付け直す（§8）
6. サイト `ATOM` を選ぶ → 右の「基本設定」→ 物理パスを `D:\Systems\ATOM\app` に変更
7. サイト `ATOM` の「ログ」→ ディレクトリを `D:\Systems\ATOM\iislogs` にして「適用」
8. サーバー名の「ログ」→ ディレクトリを `D:\ServerLogs\IIS\Sites` にして「適用」
9. サイトを開始し、`http://localhost:8080/` で表示を確認する
10. 確認できたら、旧フォルダ（`D:\WebApps` / `D:\WebData` / `D:\IISLogs` / `D:\Deploy`）を削除する

## 7. アプリケーションプールを作る

IIS マネージャー →「アプリケーション プール」→「アプリケーション プールの追加」

| 項目 | 値 |
|---|---|
| 名前 | `AtomAppPool` |
| **.NET CLR バージョン** | **.NET CLR v4.0.30319** |
| マネージド パイプライン モード | **統合** |

| 項目 | 値 | 理由 |
|---|---|---|
| **32 ビット アプリケーションの有効化** | **False** | 64bit で動かす |
| ID | `ApplicationPoolIdentity` | 既定のまま。§8 で権限を与える |

## 8. フォルダの権限を与える

配置先フォルダ `D:\Systems\ATOM\app` に、アプリケーションプールの ID を追加します。

> 追加するとき、「場所」は**このサーバーのコンピューター名**にすること（既定のドメインのままだと見つからない）。

| アカウント | 権限 |
|---|---|
| `IIS AppPool\AtomAppPool` | **読み取りと実行** |

> 先に `D:\Systems` / `D:\ServerLogs` の権限継承を切っておくこと（§5-1「着手前の確認」）。
> **他プロジェクトのアプリケーションプールには、ATOM のフォルダの権限を付けない。**

書き込みが要るのは次だけです。必要なときのみ付けてください。

| 対象 | 権限 | 用途 |
|---|---|---|
| `D:\Systems\ATOM\logs`（`Log.FolderPath`） | 変更 | ファイルログを使うとき |
| SVF の監視フォルダ（共有） | 変更 | 帳票出力 |

> **配置先フォルダ全体に書き込み権限を与えないでください。**

### 8-1. SVF 共有への接続には資格情報が必要（2026-10-21 判明）

**新サーバーから SVF の共有へは、そのままでは繋がりません。**資格情報の入力を求められます。

| | 結果 |
|---|---|
| 開発者の PC → SVF 共有 | そのまま通る |
| **新サーバー → SVF 共有** | **資格情報が必要** |

新サーバー（クラウド）と SVF サーバー（社内）で認証の土台が違うためです。

#### 対応

| 案 | 内容 | 評価 |
|---|---|---|
| **A** | **アプリケーションプールの ID を、SVF 共有に権限のあるアカウントにする** | **推奨。**設定が 1 箇所で済み、見通しがよい |
| B | `cmdkey` でアプリケーションプールの ID に資格情報を保存する | 動くが、誰がどの資格情報を持つか見えにくい |
| C | 新サーバーをドメインに参加させる | 影響が大きい。インフラ側の判断 |
| D | SVF 側の共有を広く開放する | **本番共有のため行わない** |

**A を採る。**IIS マネージャー → アプリケーション プール → 詳細設定 → **ID** → カスタムアカウント。

> `net use` で作った接続は**実行したユーザーのセッション限定**です。
> 手元で繋がっても、**IIS からは繋がりません。**必ずアプリケーションプール側で設定してください。

#### 確認方法

**`/Pages/Report/SvfConnectionTest.aspx`** を開くと、
**実際に動いている実行アカウント**と**監視フォルダを参照できるか**が表示されます。

#### 監視フォルダのパス

SVF サーバーには**名前が付いておらず、IP で参照する運用**です。
`Web.config` の `Svf.WatchFolderPath` も **IP で記述**します。

> IP 直書きは、将来 SVF サーバーを移したときに効かなくなります。
> 本番運用に入る前に、DNS または `hosts` への登録を検討してください。

### 独立したサイトにする場合

IIS マネージャー →「サイト」→「Web サイトの追加」

| 項目 | 値 |
|---|---|
| サイト名 | `ATOM` |
| アプリケーション プール | `AtomAppPool` |
| 物理パス | `D:\Systems\ATOM\app` |
| ポート | `8080`（§5-1 の台帳で空き番号を確認する） |

### 既定サイトの下に置く場合

「Default Web Site」を右クリック →「アプリケーションの追加」

| 項目 | 値 |
|---|---|
| エイリアス | `atom` |
| アプリケーション プール | `AtomAppPool` |
| 物理パス | `D:\Systems\ATOM\app` |

URL は `http://（サーバー）/atom/` になります。

> **どちらでも構いませんが、独立したサイトのほうが切り分けが楽です。**（ATOM は独立したサイトに決定済み）

### 9-1. IIS のログの出力先

IIS のログは、**システムごとのもの**と**サーバー共通のもの**に分けて置きます。

| ログ | 既定の場所 | 中身 | 扱い |
|---|---|---|---|
| **サイトのアクセスログ** | `C:\inetpub\logs\LogFiles` | サイトへの要求の記録 | **サイトごとに `D:\Systems\（システム）\iislogs`** |
| **サイトの既定ログ** | 同上 | 出力先を個別に指定していないサイトの分 | **`D:\ServerLogs\IIS\Sites`**（指定漏れの受け皿） |
| 失敗した要求のトレース | `C:\inetpub\logs\FailedReqLogFiles` | 調査用の詳細ログ。**既定では無効** | 使うときだけ、サイトごとに `D:\Systems\（システム）\iislogs\FailedReq` |
| HTTPERR | `C:\Windows\System32\LogFiles\HTTPERR` | IIS に届く前に弾かれた要求 | **C のまま**。容量が小さく、移すにはレジストリ変更と再起動が要る |
| イベントログ | Windows 標準 | アプリケーションプールの停止・異常終了など | **そのまま**（イベント ビューアーで見る） |
| 構成の履歴 | `C:\inetpub\history` | IIS 設定の自動バックアップ | **そのまま**。数 MB 程度 |

#### 設定（IIS マネージャー）

1. **サイトのアクセスログ:** サイト `ATOM` を選ぶ →「ログ」→ ディレクトリを `D:\Systems\ATOM\iislogs` →「適用」
2. **サイトの既定ログ:** 左のツリーで**サーバー名**を選ぶ →「ログ」→ ディレクトリを `D:\ServerLogs\IIS\Sites` →「適用」
3. **失敗した要求のトレース（使うときだけ）:** サイト `ATOM` を選ぶ → 右の「失敗した要求のトレース」→ ディレクトリを `D:\Systems\ATOM\iislogs\FailedReq`

指定したフォルダの下に `W3SVC（サイトID）\` が作られ、その中に日ごとのファイルが出ます。

### 9-2. 古いログの削除

**IIS はログを自動で削除しません。**放っておくと増え続けます。

- 保存期間は**お客様の運用ルールに合わせる**（2026-10-23 時点で確認中。例: 90 日）
- 決まったら、タスク スケジューラで古いログを削除するタスクを設定する（手順は保存期間の決定後に追記）
- 対象は `D:\Systems\（各システム）\iislogs`・`logs` と `D:\ServerLogs\IIS`

## 12. うまくいかないとき

| 症状 | 原因 | 対応 |
|---|---|---|
| `.aspx` のソースがそのまま表示される | **ASP.NET 4.8 が未インストール** | §3 で機能を追加 |
| HTTP 500.19 | `Web.config` の書式誤り、または必要な IIS 機能が無い | エラー画面の該当行を見る |
| HTTP 500.21（ハンドラーが不正） | ASP.NET の登録が済んでいない | `aspnet_regiis -i` を実行 |
| HTTP 403.14 | 既定ドキュメントが無い | `Default.aspx` があるか確認 |
| HTTP 404 | パス・エイリアスの誤り | 物理パスを確認 |
| ログイン画面は出るがログインできない | DB へ繋がっていない | 接続文字列・ファイアウォール・SQL Server の認証方式 |
| 画面が崩れる | `Content` / `Scripts` が配置されていない | 発行フォルダを確認 |
| 日本語が文字化けする | 配置時にファイルが壊れた | コピーし直す |
| Excel の取込で失敗する | サイズ上限 | `maxRequestLength`（現在 10MB） |
| SVF へ書き込めない | 共有の権限 | §8 の「SVF 共有への権限について」 |
| 急にログアウトする | アプリケーションプールの再利用 | §7 のタイムアウト設定 |

### エラーの詳細を見たいとき

`customErrors` は `RemoteOnly` なので、**サーバー上のブラウザで開けば詳細が出ます。**
リモートから詳細を見るために `Off` にするのは、確認が済んだら必ず戻してください。
