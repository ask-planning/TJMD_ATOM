# ATOM 開発基本方針

- **制定日**: 2026-08-12 / **版**: 1.0
- **対象**: ATOM リプレイス（ASP.NET Web Forms / VB.NET / .NET Framework 4.8.1 / SQL Server / SVF）
- **主読者**: AIエージェント。副次的に人間の開発者（プロンプトの説明資料を兼ねる）
- **目的**: 誰が・いつ・何回依頼しても同じ実装が出てくる状態（再現性）をつくること

> 本書はリポジトリを新規構成として立て直すにあたり、ゼロから作成した版です。
> `Backup\docs\ATOM_コーディング規約_v2.md` は**旧版（参照専用）**とし、本書を唯一の正とします。

## 第1部 AIエージェント向け 実行ルール

### 1.1 判断の優先順位

矛盾したときは、必ずこの順で決める。

| 順位 | 情報源 | 適用範囲 |
|---|---|---|
| **1** | **画面設計書**（`docs/specs/`） | 何を作るか（仕様・項目・振る舞い） |
| **2** | **本書** | どう書くか（規約・構成・命名） |
| **3** | 既存コード | 上記2つが沈黙している部分のスタイル |

- 設計書と既存コードが食い違う場合は、**設計書に従い**、食い違いを報告する。
- 既存コードが本書に反していても、**依頼範囲内で触った箇所のみ**本書に寄せる。範囲外は触らない。
- `Backup\` 配下は旧版であり、**参照はしてよいが編集しない**。

### 1.2 絶対に守ること

1. **データベースを勝手に変更しない。** DBは既に存在する。`CREATE` / `ALTER` / `DROP` / `TRUNCATE` を含むDDLの生成・実行、マイグレーションスクリプトの追加、テーブル・列の新設提案を伴う実装をしない。必要と判断した場合は**実装を止めて「要確認」として報告**する。
2. **本番環境（DB / IIS / ファイルサーバ）への直接操作を提案も実行もしない。** 適用手順は手順書として出力し、実行は人間が行う。
3. **接続文字列・パスワード・APIキー・個人情報を出力に含めない。** 例示は `Password=***` の形にマスクする。
4. **SQL の値は必ず `SqlParameter` にする。** 文字列連結・`String.Replace` による埋め込みは全面禁止。
5. **推測で実装しない。** 設計書から読み取れない箇所は「要確認」として質問する（§1.4）。推測を含む説明をする場合は「推測」と明示する。
6. **依頼されていないファイルを変更しない。** 「ついでの整形」「未使用変数の削除」も禁止。差分は最小に保つ。
7. **ファイルを作る前に §3 フォルダ構成を参照し、定められた場所に置く。** 該当する置き場が無いときは、勝手にフォルダを新設せず確認する。
8. **破壊的操作（DELETE / UPDATE / ファイル削除）を含むコードを生成したら、その旨を必ず明記する。**
9. **1回の変更で扱う目的は1つだけ。** 機能追加とリファクタリングを混ぜない。

### 1.3 画面作成依頼の受け方

画面の作成・改修は、**必ず画面設計書（Markdown）を受け取ってから**着手する。設計書なしの依頼が来た場合は、設計書の提示を求める。

受領時の手順は以下の通り。**この順序を省略しない。**

1. **保存する** — 受け取った設計書を、そのまま `docs/specs/<menuNo>_<画面名>.md` としてローカルに保存する（§3.2）。原文は改変しない。
2. **読み合わせる** — 設計書と本書・既存コードを突き合わせ、矛盾・不足・曖昧な点を洗い出す。
3. **質問する** — 洗い出した内容を「要確認事項」として番号付きで提示する。**推測で埋めない。**
4. **追記する** — 回答を得たら、設計書末尾の「確認事項・回答履歴」に日付・質問・回答の形で追記し、保存し直す（§3.3）。
5. **実装する** — 確定した設計書に基づいて実装する。

### 1.4 「要確認」の書き方

```
## 要確認事項
| # | 箇所 | 内容 | こちらの想定（推測） |
|---|---|---|---|
| 1 | 項目一覧 経費区分 | 必須／任意の記載がありません | 任意（既存テーブルがNULL許容のため）と推測 |
| 2 | 削除ボタン | 論理削除か物理削除か不明です | 論理削除と推測 |
```

想定を書く場合は必ず「推測」と明示する。想定が書けない場合は空欄でよい。

### 3.1 配置ルール

- 画面は必ず `src/Atom.Web/Pages/<領域>/` の下に置く。`Atom.Web` 直下への新規 `.aspx` 追加は禁止（既存の `Default.aspx` を除く）。
- 1画面 = `.aspx` + `.aspx.vb` + `.aspx.designer.vb` の3点セット。designer は Visual Studio が生成するもので、**手編集しない**。
- 画面間で共有する処理は `Atom.Web/Common/` に置く。コピー＆ペーストによる再利用は禁止。
- SQL文の生成は `Atom.Data/Sql/`、実行は `Atom.Data/Repositories/` に分ける。
- 帳票処理は `Atom.Report/` に集約する。画面から SVF の API を直接呼ばない。

### 3.2 設計書の保存

- 保存先: `docs/specs/<menuNo>_<画面名>.md`（例: `docs/specs/907_輸入経費コード登録.md`）
- menuNo が無い画面は `docs/specs/<画面名>.md`
- **受領したらまず保存する。** 実装より先。原文は改変しない。

### 3.3 設計書への追記形式

質問への回答を得たら、設計書の**末尾**に以下を追記する。本文は書き換えず、履歴として残す（後から「元の指示が何だったか」を追えるようにするため）。

```markdown
---
## 確認事項・回答履歴

### 2026-08-12
| # | 確認内容 | 回答 | 反映箇所 |
|---|---|---|---|
| 1 | 経費区分は必須か任意か | 任意 | 項目一覧 |
| 2 | 削除は論理削除か | 論理削除（delete_flag を立てる） | ボタン動作 |
```

回答によって本文の記載が明確に誤りだと分かった場合のみ、本文も修正し、「反映箇所」に修正した旨を書く。

## 4. VB.NET コーディング規約

### 4.1 コンパイラ設定（必須）

全 `.vb` ファイルの先頭に宣言し、プロジェクト設定にも同じ値を設定する。

```vb
Option Strict On
Option Explicit On
Option Infer Off
```

- 文字コードは **UTF-8（BOM付き）**、改行は **CRLF**。
- インデントは半角スペース4。タブ禁止。

### 4.2 命名規則

| 対象 | 記法 | 例 |
|---|---|---|
| 名前空間 / クラス / モジュール / 構造体 | PascalCase | `ExpenseCodeRepository` |
| メソッド（Sub / Function） | PascalCase | `SelectByKey` |
| プロパティ | PascalCase | `IsDecided` |
| 引数 / ローカル変数 | camelCase | `tenpoCode` |
| プライベートフィールド | `_camelCase` | `_connectionString` |
| 定数（Const） | PascalCase | `TransactionTimeoutSeconds` |
| 列挙型 / メンバー | PascalCase | `ShukkaMode.Selected` |
| 真偽値 | `Is` / `Has` / `Can` 始まり | `IsCanceled` |

**禁止**

- VB 側の識別子でのスネークケース（`tenpo_code_sub` → `tenpoCodeSub`）
  - ただし **DBのテーブル名・列名はスネークケースのまま**扱う。文字列リテラルとして現れる分には変更しない。
- 定数への `C_` プレフィックス、大文字スネーク（`C_TRAN_TIMEOUT` → `TransactionTimeoutSeconds`）
- 型・アクセス修飾子を省略した `Dim`（`Dim Lg As ...` → `Private ReadOnly _logic As ...`）
- 難解な英単語

**ローマ字の扱い**

業務用語はローマ字を許容するが、**ヘボン式に統一**する。

| 語 | 採用表記 |
|---|---|
| 受注残 | `Juchuzan` |
| 対象 | `Taisho` |
| 種別 | `Shubetsu` |
| 出荷 | `Shukka` |
| 配送依頼 | `HaisoIrai` |
| 物件 | `Bukken` |

綴り誤りは見つけたら修正する（`Lavel` → `Label`、`Dicide` → `Decide`）。

### 4.3 記述スタイル

**必須**

- インスタンスメンバーの参照には常に `Me.` を付ける。
- 文字列結合は `&` を使う。`+` は禁止（`String + Object` の暗黙変換事故を防ぐため）。
- 3つ以上の連結、またはループ内の連結は `String.Concat` / `StringBuilder` / `String.Format` を使う。
- `Call` キーワードを使わない。
- リソース（`SqlConnection` / `SqlCommand` / `SqlDataReader` / `StreamWriter` 等）は必ず `Using` で囲む。`Finally` での手動 `Dispose` は禁止。
- 再送出は `Throw`。**`Throw ex` は禁止**（スタックトレースが失われるため）。
- 空の `Catch`（握りつぶし）は禁止。
- マジックナンバー・区分値は `Const` または `Enum` に切り出す。

**推奨**

- 1メソッドは50行以内を目安。
- ネストは3段までを目安。

### 4.4 コメント

- Public / Protected 要素には**日本語の XML ドキュメントコメント**を付ける。
- `<param>` と `<returns>` は本文を必ず書く。空タグ禁止。実在しない引数の `<param>` を書かない。
- `<returns>` に型名だけを書かない（何を返すのかを書く）。
- コード内コメントは「なぜそうするか」を書く。分岐コメントは「Aのとき / Bのとき」の形式。

```vb
'生産指示済みのとき
If ... Then
    ...
'生産指示未済のとき
Else
    ...
End If
```

- **コメントアウトした旧コードを残さない。** 履歴は Git で追う。
- **変更履歴コメントをコード内に書かない**（`'2023/10/25 田尻 追加` 等）。コミットメッセージで管理する。

### 4.5 `#Region`

以下の順でグループ化する。

```
#Region "定数"
#Region "フィールド"
#Region "プロパティ"
#Region "コンストラクタ"
#Region "イベントハンドラ"
#Region "参照系"
#Region "更新系"
#Region "内部処理"
```

## 5. 画面層（ASP.NET Web Forms）

### 5.1 画面デザインはマークアップで定義する（最重要）

**画面は Visual Studio のデザイナ／ソースビューから編集できる状態を保つこと。**

**必須**

- コントロールの配置・種類・見た目は、すべて `.aspx` / `.ascx` のマークアップに**静的に**記述する。
- **コードビハインドでコントロールを動的生成しない。** 以下は禁止。
  - `New TextBox()` などによるコントロールのインスタンス生成
  - `Controls.Add(...)` / `Controls.Remove(...)`
  - `GridView.Columns.Add(...)` による列の動的追加
  - コードによる `CssClass` の文字列組み立てでのレイアウト制御（見た目は CSS クラスで切り替える）
- 表示の出し分けは、**マークアップに全パターンを書いておき、`Visible` / `Enabled` を切り替える**方法で実現する。

```vb
' 良い例: マークアップに定義済みのコントロールの状態を変えるだけ
Me.pnlApproval.Visible = Me.CurrentUser.CanApprove
Me.btnSave.Enabled = Not Me.IsReadOnly
```

**例外（動的操作を許可する場合）**

以下に該当するときのみ、コードビハインドでの操作を認める。**該当した理由をコード内コメントに必ず書く。**

1. **マークアップでは構造上表現できない場合**（可変列数のグリッド、設定値で件数が変わる明細行など）。
2. **ポストバック・イベント発生後の状態変更**（`Click` / `SelectedIndexChanged` / `RowDataBound` 等の中での `Visible`・`Text`・`DataSource` の変更）。これは通常の動作であり制限しない。
3. **バインド時の値設定**（`FindControl` で取得したコントロールへの値の詰め込み）。

```vb
' 例外2に該当: 保存ボタン押下後の状態反映のため
Private Sub btnSave_Click(sender As Object, e As EventArgs) Handles btnSave.Click
    Me.lblMessage.Text = "保存しました。"
    Me.lblMessage.Visible = True
End Sub
```

- `.aspx.designer.vb` は Visual Studio が自動生成する。手編集せず、マークアップとの同期が崩れたら VS 側で再生成する。

### 5.2 責務

- **業務ロジックを `.aspx.vb` に書かない。** `Atom.Core` / `Atom.Data` に置く。`.aspx.vb` の責務はイベント受付・入力値の詰め替え・結果表示のみ。
- `Page_Load` の初期化処理は `If Not IsPostBack Then` で囲む。
- 共通レイアウトは `Site.Master`、共通ヘッダーは `HeaderControl.ascx`。画面タイトル・ヘッダー色は `Page_Load` でヘッダーコントロールへ設定する。

### 5.3 必須の実装事項

- **`Shared`（静的）変数に画面やユーザーの状態を保持しない。** 全ユーザーで共有され、データ混在事故を起こす。
- グリッドの列は**列名で識別**する。`Cells(7)` のようなインデックス直指定は禁止。`e.Row.FindControl("lblShukkaDate")` または `DataBinder.Eval(e.Row.DataItem, "shukka_date")` を使う。
- 画面出力は HTML エスケープする。`Literal` の `Mode` は `Encode` を既定とする。
- `Page_Init` で `ViewStateUserKey` にセッションIDを設定する（CSRF対策）。
- 入力検証はクライアント側（Validator）だけに依存せず、**サーバー側でも必ず再検証**する。
- 更新系ボタンは二重送信を防止する。
- 削除はクライアント側の `confirm` に加え、**サーバー側でも再確認**する。
- 権限チェック（menuNo 単位）は `BasePage` で一元化し、画面表示だけでなく**処理の入口でも判定**する。ボタンの非表示は認可ではない。
- 一覧のページングとソートはサーバー側（SQL）で行う。
- ViewState は必要な項目のみ有効にし、GridView の肥大化を避ける。
- 画面遷移は `Response.Redirect(url, False)` + `Context.ApplicationInstance.CompleteRequest()` を使う（第2引数 `True` は `ThreadAbortException` を発生させるため）。
- 例外の詳細（スタックトレース・SQL文）を画面に出さない。ユーザーには日本語の定型メッセージ、詳細はログへ。

### 5.4 コントロールID接頭辞

記法は `接頭辞 + PascalCase`（アンダースコアなし）。例: `btnSave`, `gvExpenseCode`, `ddlTruckShubetsu`

```
lbl  Label            txt  TextBox          ddl  DropDownList
chk  CheckBox         cbl  CheckBoxList     rbl  RadioButtonList
btn  Button           lnk  LinkButton       img  Image
gv   GridView         lv   ListView         rpt  Repeater        dl  DataList
hdn  HiddenField      pnl  Panel            ph   PlaceHolder
upn  UpdatePanel      lit  Literal          fu   FileUpload
rfv  RequiredFieldValidator   rev  RegularExpressionValidator
cv   CustomValidator          vsm  ValidationSummary
cnt  Content
```

**デザイナ既定名（`Label4`, `GridView1` 等）の残存を禁止する。** コミット前に必ず改名する。

### 5.5 WinForms からの持ち込み禁止

| WinForms のコード | Web での扱い |
|---|---|
| `MessageBox.Show(...)` | 画面上のメッセージ領域 または クライアントスクリプト |
| `Cursor.Current = Cursors.WaitCursor` | クライアント側のローディング表示 |
| 再描画ハック（`Me.Size = New Size(...)`） | 不要。CSS で解決する |
| `Form.Show()` / `ShowDialog()` | ページ遷移 または モーダル |
| フォームの Public フィールド経由の値渡し | クエリ文字列（**改ざん前提で必ずサーバー側再検証**）／セッション |
| `Application.Exit` | ログアウト（セッション破棄） |

## 6. 設定（Web.config）

**設定値をコードに直書きしない。** 環境で変わりうる値はすべて `Web.config` から取得する。

### 6.1 ログ

ログの**出力先は `Web.config` で指定する**。コード側は `ILogWriter` を通してのみ書き込み、各画面から直接ログを書かない。

```xml
<appSettings>
  <!-- ログの書き出し先。Sql / File / Trace のいずれか -->
  <add key="Log.Writer" value="Sql" />
  <!-- Log.Writer = Sql のとき: 出力先の接続名とテーブル名 -->
  <add key="Log.ConnectionName" value="AtomDb" />
  <add key="Log.TableName" value="t_application_log" />
  <!-- Log.Writer = File のとき: 出力先フォルダ（サーバー上の絶対パス） -->
  <add key="Log.FolderPath" value="" />
  <!-- 記録する最小レベル。Information / Warning / Error -->
  <add key="Log.MinimumLevel" value="Information" />
</appSettings>
```

- 起動時（`Global.asax` の `Application_Start`）に `Log.Writer` を読み、対応する `ILogWriter` を `Logger.Register` へ登録する。
- 設定値が不正・未設定のときは、起動時に例外を投げて気づけるようにする（黙って既定値で動かさない）。
- ログ出力の失敗が業務処理を止めないこと。
- **ログに接続文字列・パスワード・個人情報を平文で出力しない。** 実行SQLとパラメータを記録する場合も、機密に当たる値はマスクする。

### 6.2 メール

**メール送信の有無を `Web.config` で切り替えられるようにする。** 開発・検証環境で実際の宛先へ誤送信することを防ぐため。

```xml
<appSettings>
  <!-- メール送信を行うか。false のとき送信せずログのみ記録する -->
  <add key="Mail.Enabled" value="false" />
  <!-- 差出人アドレス -->
  <add key="Mail.FromAddress" value="" />
  <!-- 検証用: 値があるとき、全宛先をこのアドレスへ差し替える（本番は空にする） -->
  <add key="Mail.RedirectTo" value="" />
</appSettings>

<system.net>
  <mailSettings>
    <smtp deliveryMethod="Network">
      <network host="" port="25" enableSsl="false" />
    </smtp>
  </mailSettings>
</system.net>
```

- `Mail.Enabled` が `false` のときは、**送信せず**「送信を抑止しました」を宛先・件名とともにログへ記録する。呼び出し側から見て例外にはしない。
- `Mail.RedirectTo` に値があるときは、元の宛先を件名または本文冒頭に残したうえで差し替える。
- SMTP の資格情報が必要な場合も `Web.config` に置き、**平文のままコミットしない**（§6.4）。

### 6.3 帳票（SVF）

```xml
<appSettings>
  <!-- SVF 帳票定義ファイルの格納フォルダ -->
  <add key="Svf.FormFolderPath" value="" />
  <!-- 一時ファイルの作業フォルダ -->
  <add key="Svf.WorkFolderPath" value="" />
</appSettings>
```

- 出力先パス・一時ファイルパスをコードにハードコードしない（`C:\temp\...` 等は禁止）。

### 6.4 接続文字列と機密情報

**必須**

- 接続文字列は `connectionStrings` の `AtomDb` から取得する。コードに直書きしない。
- **接続文字列の実値（特にパスワード）をリポジトリにコミットしない。** 次のいずれかを用いる。
  - `configSource` による外部ファイル化＋`.gitignore` 登録
  - `Web.<環境>.config` 変換によるデプロイ時差し込み
  - Windows 認証（`Integrated Security=True`）への切り替え
- リポジトリに含める `Web.config` には、値をマスクした状態（`User ID=***;Password=***`）で置く。
- 誤ってコミットした場合は、**当該アカウントのパスワードを変更**する。ファイルを消すだけでは履歴に残る。

## 7. データアクセス（SQL Server）

### 7.1 データベース変更の禁止（必須）

DBは既に存在し、他システムからも参照されうる。

- **DDL（`CREATE` / `ALTER` / `DROP` / `TRUNCATE`）を生成・実行しない。**
- **テーブル・列・インデックス・ストアドの追加や変更を伴う実装をしない。**
- `db/schema/` は**既存DBの参照用スナップショット**であり、ここを編集しても実DBは変わらない。編集しない。
- 実装に不足があると判断した場合は、実装を止めて「要確認」として報告する（§1.4）。
- テストデータ・実データをリポジトリにコミットしない。

### 7.2 SQL の組み立て（必須）

**値は必ず `SqlParameter` にする。文字列連結・`String.Replace` による埋め込みを全面禁止する。**

```vb
' 禁止
.AppendLine("WHERE truck_type = '" + truckShubetsu + "'")
query.Replace("@ShukkaDate", "shukka_date = '" & shukkaDate & "'")
```

```vb
' 正しい書き方
Const SelectCabiSinkSql As String =
    "SELECT cabi_count, sink_count " &
    "FROM dbo.m_truck_shubetsu " &
    "WHERE truck_type = @TruckType"

Using command As New SqlCommand(SelectCabiSinkSql, connection, transaction)
    command.Parameters.Add("@TruckType", SqlDbType.NVarChar, 20).Value = truckType
    ...
End Using
```

- 型は `Parameters.Add(名前, 型, 長さ)` で明示する。`AddWithValue` は型推論による暗黙変換でインデックスが効かなくなるため使わない。
- NULL は `DBNull.Value` を使う。
- `SELECT *` 禁止。必要な列を明示する。

**動的にSQLを組む場合**

- 条件の有無で `WHERE` 句を組み替える場合も、**値は必ずパラメータ**にする。組み立ててよいのは構文部分のみ。

```vb
Dim conditions As New List(Of String)()
If shukkaDate.HasValue Then
    conditions.Add("HI.shukka_date = @ShukkaDate")
    command.Parameters.Add("@ShukkaDate", SqlDbType.Date).Value = shukkaDate.Value
End If
```

- ソート列やテーブル名を可変にする場合は**ホワイトリスト照合**を必須とする。外部入力をそのまま埋め込まない。

### 7.3 型の扱い

- 日付は `Date` / `Date?`、真偽値は `Boolean` / `Boolean?` で受け渡す。`String` で持ち回らない。
- DB の NULL は `Nullable(Of T)` で表現する。`IsDBNull` の判定は取得箇所で完結させ、上位に `Object` のまま渡さない。
- 番兵値（`'1900/01/01 0:00:00'` 等）を新規に増やさない。既存データの都合で必要な場合は定数化する。

### 7.4 接続・トランザクション

- `SqlConnection` / `SqlCommand` / `SqlDataAdapter` は `Using` で囲む。
- **接続の Open / Close をデータアクセスメソッドごとに行わない。** トランザクション単位を呼び出し側で制御できるようにする。
- 複数テーブルを更新する処理は必ずトランザクションで囲む。
- 接続オブジェクトをフィールドやセッションに保持しない。リクエスト内で完結させる。
- `NOLOCK` を安易に使わない。使う場合は理由をコメントに残す。

### 7.5 メソッド命名

| レイヤ | 役割 | 命名 | 例 |
|---|---|---|---|
| `Sql/` | SQL文字列の生成のみ | `Create○○Sql` | `CreateSelectBukkenIchiranSql` |
| `Repositories/` | SQLの実行 | `Select` / `Insert` / `Update` / `Delete` / `Merge` で始める | `SelectBukkenIchiran`, `UpdateShukkaDate` |
| `Atom.Core` | 業務処理 | 動詞 + 目的語の PascalCase | `DecideShukkaDate` |

- 論理削除は `Delete` ではなく **`SoftDelete`** を接頭辞に使い、物理削除と区別する。
- 排他制御は更新日時（または RowVersion）による**楽観ロック**とする。競合時は専用の例外クラス（`ConcurrencyException`）を送出する。

## 8. 例外処理とログ

- 再送出は `Throw`。**`Throw ex` は禁止。**
- 例外を握りつぶさない。`Catch` でメッセージ表示のみ行い処理を続行するのは禁止。継続できない場合は処理を中断する。
- `Catch ex As Exception` で握る場合は、必ず「ログ記録＋再送出」または「明示的な業務的リカバリ」のいずれかを行う。
- ログ出力は `Logger` 経由のみ。各画面から書き出し先へ直接書かない。

```vb
Catch ex As SqlException
    Logger.WriteError(LogSource, "物件一覧の取得に失敗しました。", ex, loginCode)
    Throw
End Try
```

## 付録A: 人間の開発者向け補足（なぜこの規約なのか）

- **`Option Infer Off` を採用する理由** — 型推論は簡潔だが、`Option Strict On` と併用しても「右辺の型が変わったときに左辺の型が黙って変わる」挙動が残る。旧 Access/VBA からの移植コードは型の意図が曖昧な箇所が多く、明示を強制したほうが移植時の事故が減る。
- **`AddWithValue` を避ける理由** — 型と長さが推論されるため、`nvarchar` パラメータが `varchar` 列と比較されて暗黙変換が発生し、インデックスが使われなくなる。件数の多いテーブルで性能問題になりやすい。
- **画面を動的生成しない理由** — Web Forms の最大の資産は「デザイナで開いて画面が見える」こと。コードでコントロールを生成すると、デザイナでは何も見えず、`.aspx` を読んでも画面が分からなくなる。保守担当が変わったときの読み解きコストが跳ね上がる。加えて、動的生成したコントロールは `Page_Init` での再生成を毎回正しく行わないと ViewState が復元されず、原因の掴みにくい不具合を生む。
- **DB変更を禁止する理由** — 既存DBは他システム・既存 Access 資産からも参照されている可能性がある。片側のアプリ都合でスキーマを変えると、影響範囲が本システム内で閉じない。
- **設計書を最優先にする理由** — 既存コードは「現時点の実装」であって「あるべき仕様」ではない。旧 Access からの移植では、既存実装に業務上のバグや暫定対応が含まれていることが前提。仕様の正は人間が書いた設計書に置く。
- **メール送信を config で切れるようにする理由** — 検証環境から実顧客・実取引先へ誤送信する事故は取り返しがつかない。既定値を `false` にし、明示的に有効化しないと飛ばない構造にしておく。

## 付録B: 本書の運用

- 本書は `CLAUDE.md` から参照される。AIへの依頼時に毎回貼り直す必要はないが、長いスレッドでは冒頭で本書の参照を促すこと。
- 規約に例外を設ける場合は、コードにコメントで理由を残し、本書にも追記する。「暗黙の例外」を作らない。
- 本書と実装が乖離したら、どちらかを直す。放置しない。
