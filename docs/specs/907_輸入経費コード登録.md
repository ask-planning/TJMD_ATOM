| コントロール | 値集合ソースの種類 | 値集合ソース | 列幅 |

## 5. ボタン仕様

旧画面には「登録」「更新」「削除」ボタンが**無い。**一覧の編集は Access のフォーム標準動作（行を移動した時点で保存）で行われている。

### 5.1 閉じる（`btn_close`）

#### 現行Access処理

```vb
Private Sub btn_close_Click()

    If IsNull(Me![login_code]) Then
        Call btn_setsuzoku_Click
    End If

    If IsNull(Me![return_form_name]) Then
        strFormName = "F_3_輸入諸経費入力_MAIN"
        intMenuNo = 0
        intMenuNoSeq = 0
    Else
        strFormName = Me![return_form_name]
        intMenuNo = 301
        intMenuNoSeq = 0
    End If
    strOpenMode = "OC"
    Call form_open_close("F_M_経費コード登録_MAIN", strFormName, strOpenMode, "NULL")

End Sub
```

| 段階 | 内容 |
|---|---|
| 入力チェック | なし（`login_code` が空なら再接続を呼ぶのみ） |
| 処理 | 戻り先を決めて本画面を閉じ、戻り先を開く |
| 完了後 | `return_form_name` が空 → 輸入諸経費入力（301）。空でない → `return_form_name` の画面 |

- 戻り先がスタートメニューでも `intMenuNo = 301` を設定しているが、共通処理 `form_open_close` が `next_form = "F_0_START_MENU"` のとき `intMenuNo = 0` に戻すため実害は無い
- **閉じた時点で編集中の行は Access が自動保存する**（Access 標準動作。VBA に記述は無い）

#### Web版仕様

| 段階 | 内容 |
|---|---|
| 入力チェック | なし |
| 処理 | 遷移元へ戻る。遷移元は共通ヘッダーの戻り先の仕組みで保持する |
| 完了後 | スタートメニューから来た場合はメニューへ、輸入諸経費入力から来た場合は 301 へ（§13 C-16） |
| 未保存の編集 | 編集中の行がある場合の扱いは §13 C-15 |

## 6. 登録・更新処理

### 6.1 現行Access

| 項目 | 内容 |
|---|---|
| 更新方式 | **サブフォームがテーブルに直結しており、Access 標準動作で直接 INSERT / UPDATE する** |
| 呼ぶストアド | なし（`.adp` の VBA に該当なし） |
| 更新対象 | `tbl_m_import_keihi_code` |

### 6.2 更新日・更新者の設定（VBA から実測）

```vb
Private Sub keihi_code_text_AfterUpdate()
    Me![update_ymd] = Now()
    Me![update_login] = Forms![F_M_経費コード登録_MAIN]![login_code]
End Sub

Private Sub keihi_kbn_AfterUpdate()
    （同上）
End Sub

Private Sub pk_keihi_code_AfterUpdate()
    （同上）
End Sub
```

| 編集した項目 | `update_ymd` / `update_login` の更新 |
|---|---|
| 伝票コード `pk_keihi_code` | される |
| 経費名称 `keihi_code_text` | される |
| 区分 `keihi_kbn` | される |
| REF `keihi_code_ref` | **されない**（AfterUpdate が無い） |
| 保険対象 `hoken_taisyo_flg` | **されない**（AfterUpdate が無い） |

- `update_ymd` はクライアント PC の時刻（`Now()`）
- REF・保険対象だけを直した場合、更新日・更新者は古いまま残る。§13 C-11

### 6.3 Web版

| 項目 | 仕様 |
|---|---|
| 更新対象 | `tbl_m_import_keihi_code`（接続文字列 `AtomDb` の接続先。検証は **ATOM_dev のみ**で行う。本番への反映は §13 C-21） |

## 7. 削除処理

### 7.1 現行Access

| 項目 | 内容 |
|---|---|
| 削除ボタン | **無い** |
| 削除の手段 | Access 標準動作（レコードセレクタで行を選んで Delete キー）。**フォームの「削除の許可」プロパティが読めないため、実際に削除できたかは不明**（§13 C-6） |
| 論理／物理 | 物理削除と推測（連結列に削除フラグに当たる列が無いため） |
| 確認メッセージ | ATOM 独自の文言は**無い**。削除できた場合は Access 標準の確認ダイアログが出る（推測）。写すべき旧文言は存在しない |
| 参照整合 | 経費コードは輸入諸経費の明細 `tbl_t_import_keihi_meisai.pk_keihi_code` から参照されている（301 のサブフォームのレコードソースから確認）。外部キー制約の有無は未確認 |

### 7.2 Web版

**削除機能を設けるかどうか未確定**（§13 C-6）。設ける場合の案は次のとおり。

| 項目 | 案 |
|---|---|
| 方式 | 物理削除（§13 C-6 の回答次第） |
| 確認メッセージ | 旧に文言が無いため新設が必要。文言は §13 C-29 で確定する |
| 使用中のコード | `tbl_t_import_keihi_meisai` で使われているコードを消してよいか §13 C-7 |
| サーバー側 | 削除直前に存在と `update_ymd` を再確認する |

## 8. 初期表示処理

### 8.1 現行Access

画面を開いたときに次の順で動く。共通処理 `form_open_close`（標準モジュール）とフォームのイベントから読み取った。

|---:|---|---|

| 4 | フォームを開く | `DoCmd.OpenForm` |
| 5 | 値の引き継ぎ | `login_code` / `login_name` / `bumon_code` / `return_form_name` を設定 |
| 6 | ボタン制御 | 権限 0 / 9 のとき `btn_koushin` 等 8 個を無効化する共通処理が走るが、**本画面には該当ボタンが無いため何も起きない**（`On Error Resume Next`） |
| 7 | `Form_Open` | `DoCmd.Maximize` |
| 8 | 一覧の読込 | サブフォームが `tbl_m_import_keihi_code` を全件読む。コンボは `tbl_m_import_keihi_code` / `View__keihi_kbn` を読む |

### 8.2 Web版

| 順 | 処理 |
