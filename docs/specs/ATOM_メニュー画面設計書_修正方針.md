# ATOM メニュー画面設計書 修正方針

## 1. システムバージョン確認処理

### ASP.NET版仕様

現行Access版で実施している以下のシステムバージョン確認処理は、ASP.NET版では**廃止する**。

- `strAtomVersion` によるクライアントバージョン管理
- `usp_system_version_no_get` の実行
- DB側最新バージョンとの比較
- 「システムが最新ではありません。」メッセージ
- 最新版コピーを促す処理

### 廃止理由

現行Access版では、利用者ごとに異なるAccessファイルを起動する可能性があるため、古いクライアントプログラムの利用防止を目的としてバージョン確認を行っている。

ASP.NET版ではサーバー上に配置された同一Webアプリケーションを全利用者が使用するため、クライアントごとのプログラムバージョン差異が基本的に発生しない。

---

# 2. Access固有UIの廃止

現行Access版で使用している以下のUI・制御は、そのまま移植しない。

| Access版 | ASP.NET版 |
|---|---|
| `InputBox` | Webログイン画面 |
| `MsgBox` | Webダイアログ／メッセージ表示 |
| `DoCmd.OpenForm` | URLルーティングによる画面遷移 |
| `DoCmd.Quit` | ログアウト処理 |
| Accessフォーム | Web画面 |
| Accessグローバル変数 | Session |

ASP.NET版では、すべてWebアプリケーションとして適切なUI・制御に置き換える。

---

# 3. ログイン画面

ATOMへアクセスした場合、最初にログイン画面を表示する。

ログイン画面では社員コードを入力する。

### 入力仕様

| 項目 | 内容 |
|---|---|
| 項目名 | 社員コード |
| 桁数 | 6桁 |
| 必須 | 必須 |
| 認証処理 | `usp_syain_jyoho_get` |
| 成功時 | メニュー画面へ遷移 |
| 失敗時 | エラー表示後、ログイン画面を維持 |

社員コードが6桁以外の場合：

> 入力桁数が不正です（６桁）。

社員コードが存在しない場合：

> 存在しない社員コードが入力されました。

---

# 4. ログイン情報管理

ログイン成功時に取得した情報はASP.NETのSessionで管理する。

現行Access版で使用されている情報については、現段階では削除せず保持する。

| Session項目 | 現行変数 | 用途 |
|---|---|---|
| LoginCode | `strLoginCode` | ログイン社員コード |
| LoginName | `strLoginName` | ログイン社員名 |
| BumonCode | `strBumonCode` | 部門コード |
| ModeKanrisya | `intModeKanrisya` | 用途詳細不明・現行仕様維持 |
| ModeAtom | `intModeAtom` | 用途詳細不明・現行仕様維持 |
| ShanghaiChotatsu | `intShanghaiChotatsu` | 用途詳細不明・現行仕様維持 |

### 備考

各種フラグについては後続画面・処理で利用されている可能性があるため、現段階では廃止しない。

リプレイスを進める中で利用箇所を確認し、用途を明確化する。

使用箇所が存在しないことが確認された場合に、改めて廃止を検討する。

---

# 5. URL直接アクセス制御

ATOM内の各画面URLへ直接アクセスされた場合も、必ずログイン状態を確認する。

```text
各画面URLへアクセス
       │
       ▼
Session確認
       │
   ┌───┴───┐
   │       │
 有効     無効
   │       │
   ▼       ▼
画面表示  ログイン画面へ
          リダイレクト
```

未ログイン状態では、メニュー画面および業務画面を直接表示しない。

例えば利用者が直接、

```text
/KeihiCode
```

等を入力した場合でも、Sessionが存在しなければログイン画面へリダイレクトする。

この認証判定は各画面個別ではなく、ATOM全体の共通処理として実装する。

---

# 6. Sessionタイムアウト

一定時間操作が行われずSessionが失効した場合、再ログインを要求する。

ただし、**Session切れによって利用者が入力中のデータを失わないことを基本方針とする。**

## 6.1 Session有効期限切れ検知

Ajax通信、画面遷移、登録処理等の実行時にSession切れを検知した場合、現在画面を破棄してログイン画面へ遷移するのではなく、現在の入力状態を維持した状態でログイン画面を表示する。

```text
業務画面で入力中
      │
      ▼
Session切れ検知
      │
      ▼
現在画面・入力内容を保持
      │
      ▼
ログイン画面を表示
      │
      ▼
再ログイン
      │
  ┌───┴────┐
  │成功     │失敗
  ▼         ▼
元画面へ    ログイン画面
復帰        維持
  │
  ▼
入力作業を継続
```

---

# 7. Session切れ時の入力内容保護

Session切れ時に入力中データを失わないため、以下の方針とする。

### 基本方針

ブラウザ上に存在する入力内容を維持したまま、ログイン処理のみ再実行する。

再ログイン成功後は、入力中だった画面へ戻り、入力作業を継続可能とする。

### 入力内容

以下のような未登録データを対象とする。

- テキスト入力値
- 選択中のプルダウン値
- チェックボックス
- 画面内で編集中の明細
- 検索条件
- その他ブラウザ上の未送信データ

Session切れだけを理由としてこれらを初期化しない。

---

# 8. Session切れ時のログイン表示方式

通常のURL直接アクセス時と、作業中のSession切れでは動作を分ける。

### URL直接アクセス／初回アクセス

```text
未ログイン
   ↓
ログイン画面へリダイレクト
```

### 業務画面操作中のSession切れ

```text
Session切れ
   ↓
現在画面を保持
   ↓
ログインUIを表示
   ↓
再ログイン
   ↓
同じ画面・同じ入力状態から作業再開
```

作業中のSession切れについては、単純なログインページへのHTTPリダイレクトは行わない。

入力内容消失防止のため、モーダル等のログインUIを現在画面上に表示する方式を基本とする。

---

# 9. 再ログイン後の処理

再ログイン成功後、新しいSessionを生成する。

その後、ログイン前に操作していた業務画面をそのまま利用可能な状態へ戻す。

未登録の入力データを自動でDB登録することはしない。

利用者が再ログイン後、内容を確認して通常どおり登録・更新操作を行う。

---

# 10. 登録処理中にSession切れとなった場合

登録・更新ボタン押下時点ですでにSessionが切れていた場合、DB更新処理を実行しない。

```text
登録ボタン押下
      │
      ▼
Session確認
      │
  ┌───┴───┐
  │       │
有効     無効
  │       │
  ▼       ▼
登録処理  ログイン要求
          │
          ▼
       再ログイン
          │
          ▼
       元画面へ復帰
```

再ログイン後に、利用者が改めて登録操作を実施する。

これにより「ログインが切れているにもかかわらず登録だけ実行された」といった不整合を防止する。

---

# 11. ログアウト

現行画面の「終了」は、ASP.NET版では**「ログアウト」**へ変更する。

### ボタン表示文字

```text
ログアウト
```

### 処理

ログアウトボタン押下時：

1. 現在のSessionを破棄する。
2. ログイン状態を解除する。
3. ログイン画面へ遷移する。

```text
ログアウト押下
      │
      ▼
Session破棄
      │
      ▼
認証状態解除
      │
      ▼
ログイン画面表示
```

ブラウザタブを閉じる処理は行わない。

---

# 12. ログアウト時の未保存データ

画面に未登録・未保存の入力内容が存在する状態でログアウトを押下した場合については、誤操作によるデータ消失防止を考慮する。

未保存データが存在する場合は、確認ダイアログを表示することを推奨する。

> 入力中の内容は保存されていません。ログアウトしますか？

- 「はい」：入力内容を破棄してログアウト
- 「いいえ」：ログアウトせず現在画面へ戻る

※単純なメニュー画面等、未保存データが存在しない画面では確認不要。

---

# 13. ログインログ

現行Access版の以下のログ登録処理は継続する。

```text
usp_atom_login_log
```

ログイン成功後に実行する。

登録対象：

| 項目 | 内容 |
|---|---|
| 社員コード | ログインした社員コード |
| システム識別情報 | 現行ストアド仕様に準ずる |
| その他パラメータ | 現行ストアド仕様に準ずる |

ただし、Access版で渡している `strAtomVersion` はASP.NET版では廃止となるため、`usp_atom_login_log` の引数仕様について確認が必要。

### 要確認事項

`usp_atom_login_log` の第2引数が必須である場合、

- ASP.NETアプリのリリース番号を渡す
- 固定値を渡す
- ストアド側を変更する

等の対応を別途決定する。

---

# 14. 画面遷移共通処理

各画面への遷移処理はATOM共通処理とする。

遷移先画面が存在する場合：

```text
対象画面へ遷移
```

遷移先画面が未実装の場合：

> 現在未実装です。

を表示し、現在画面に留まる。

この処理はメニュー画面だけでなくATOM内の全画面で共通利用する。

---

# 15. 認証・Session関連の共通化

以下は個別画面へ実装せず、ATOM共通機能として管理する。

- ログイン状態チェック
- Session生成
- Sessionタイムアウト判定
- Session切れ時の再ログイン
- URL直接アクセス時のログイン画面リダイレクト
- ログアウト
- 未実装画面判定
- ログインユーザー情報取得

これにより、各業務画面側では認証処理を意識せず業務ロジックを実装できる構成とする。
