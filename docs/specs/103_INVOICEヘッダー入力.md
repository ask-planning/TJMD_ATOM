# ATOM_INVOICEヘッダー入力画面 設計書

- **menuNo**: 103
- **作成日**: 2026-10-19
- **作成元**: 旧 Access（`ATOM.adp`）の VBA・画面・帳票の解析結果
- **位置づけ**: SVF 帳票出力の実現性確認における先行開発の対象画面

> 本書は旧 Access 版 `F_1_上海輸入_INVOICE_HEADER` の実装を解析して起こしたものです。

## 1. 画面概要

### 1.1 画面名

| 項目 | 内容 |
|---|---|
| 画面名 | INVOICEヘッダー入力 |
| 画面ID（仮） | ATOM_INVOICEヘッダー入力 |
| 旧 Access フォーム | `F_1_上海輸入_INVOICE_HEADER` |
| 明細サブフォーム | `F_1_上海輸入_INVOICE_HEADER_SUB` |
| menuNo | 103 |

### 1.2 目的

INVOICE/PACKING 取込（menuNo=101）で本登録した INVOICE に対し、**船積みの情報と配送の段取りを登録**する。
あわせて、通関業者・配送業者・工場へ渡す**帳票を発行**する。

取込で作られた INVOICE ヘッダは `ref_no` `vessel` `return_pallet` `otsunaka_no` が未設定の状態であり、
**本画面がその中身を埋める**役割を持つ。

### 1.3 業務上の位置づけ

```text
101 INVOICE/PACKING取込
      ↓ 明細・ヘッダを登録
103 INVOICEヘッダー入力   ← 本画面
      ↓ 配送手配書・入荷明細書を発行
通関業者 / 配送業者 / 工場
```

### 1.4 Web 化に伴う主な変更

| 旧 Access | Web 版 |
|---|---|
| `DoCmd.Maximize` で最大化 | 不要。ブラウザの画面に合わせる |
| レポートをプレビュー表示して印刷 | **SVF で PDF を生成し、画面に表示**して印刷する |
| Access グローバル変数（`intMenuNo` 等） | セッションまたは画面遷移パラメータ |
| `Login_ReInput` による再接続 | 共通のセッション切れ処理 |
| ボタンの `Enabled` を共通処理で一括制御 | `BasePage` の権限判定で制御（§15） |
| InternetExplorer.Application で外部 URL を呼び出し | **要再設計**（§18 C-5） |

## 6. 画面表示時の処理

### 6.1 画面を開いたとき

| 処理 | 内容 |
|---|---|
| menuNo の設定 | 103 |
| 明細サブフォームの準備 | `usp_shanghai_invoice_header_sub_temp_create` を実行 |
| 入荷明細書ボタンの活性 | 権限で制御（§15） |
| 元INV_NO の選択肢 | `View__invoice_no_main` を設定 |

### 6.2 元INV_NO を選んだとき

旧 Access の `pk_invoice_no_main_AfterUpdate` に相当する。**本画面の中核処理**。

**処理順序**

1. **入力欄の初期化** — 船名・乙仲・金額・数量・カートン数・出荷方法・B/L DATE・返却パレットを空にする
2. **登録済みかの判定** — `usp_shanghai_invoice_sonzai_check` を実行
   - 第2パラメータ：ヘッダの件数
   - 第3パラメータ：サブヘッダの件数（0 なら「新規」とみなす）
   - 第4パラメータ：BL DATE・出荷方法の種類数
3. **整合チェック** — 第4パラメータが 2 以上なら中断
   > 同じINVOICE_NOで、BL_DATE、出荷方法が異なるPACKINGがあります。
   > PACKINGデータを修正してください。
4. **ヘッダの読み込み**
   - ヘッダ件数が 0 → **「新規登録です。」**を表示し、入力欄をすべて空にする
   - ヘッダ件数が 1 以上 → `tbl_t_shanghai_invoice_header` から読み込んで画面へ表示
5. **サブヘッダの一時データ作成** — `usp_shanghai_invoice_header_sub_temp_create`
6. **合計情報の取得** — `usp_shanghai_invoice_gokei_get`
   - カートン数・金額・数量を画面へ設定
   - **ヘッダが未登録のときのみ**、BL DATE と出荷方法も明細の集計値で埋める
7. **入力欄の色** — ヘッダが未登録のとき、BL DATE と出荷方法をグレーにする
8. **明細の再表示**

## 8. 「登 録」ボタン

### 8.1 入力チェック

| 順 | 条件 | メッセージ |
|---:|---|---|
| 1 | 元INV_NO が未入力 | INVOICE_NOを入力してください。 |
| 2 | 船名が未入力 | 船名を入力してください。 |
| 3 | 乙仲が未入力 | 乙仲を入力してください。 |

**B/L DATE・出荷方法・カートン数・返却パレットは必須ではない。**

### 8.2 ヘッダの登録

`usp_shanghai_invoice_sonzai_check` で件数を確認し、分岐する。

| 件数 | 処理 |
|---|---|
| 0 | `tbl_t_shanghai_invoice_header` へ **INSERT** |
| 1 以上 | 同テーブルを **UPDATE** |

**対象列**

| 列 | 登録 | 更新 |
|---|---|---|
| `pk_invoice_no_main` | ○ | キー |
| `ref_no` | ○ | ○ |
| `bl_date` | ○ | ○ |
| `vessel` | ○ | ○ |
| `syukka_hoho` | ○ | ○ |
| `carton_qty` | ○ | ○ |
| `return_pallet` | ○ | ○ |
| `otsunaka_no` | ○ | ○ |
| `update_ymd` / `update_login` | ○ | ○ |

### 8.3 サブヘッダの更新

`usp_shanghai_invoice_header_sub_update` を実行し、画面の明細内容を
`tbl_t_shanghai_invoice_header_sub` へ反映する。

### 8.4 印刷用INVOICE_NO の編集

**コンテナ単位で、同じコンテナに積まれた枝番をカンマで連結**して
`invoice_no_print` に設定する。

**処理**

1. `usp_shanghai_invoice_container_count` でコンテナ番号の件数を取得
2. `tbl_t_shanghai_invoice_header_sub` から `haiso_type <> 3` の行を
   コンテナ区分・コンテナNO・INVOICE_NO 順に読み込む
3. **コンテナNO が変わるまでを 1 グループ**とし、枝番だけを切り出して連結する
4. 連結結果をそのコンテナNO の行へ `UPDATE` する

**枝番の切り出し規則**

```text
INVOICE番号の 9 文字目が数値  → 10 文字目以降
                 数値でない  →  9 文字目以降
```

この規則は 101 の `pk_invoice_no_main` の切り出しと同じ考え方である。

### 8.5 配送予定日が入っている場合の外部連携

明細に配送予定日が 1 件でも入っている場合、**外部システムへ HTTP で通知**している。

```vb
URL = "http://（サーバー）:7700/dataspider/trigger/KJH_R3_ZM510?MainInvoiceNo=" & 元INV_NO
InternetExplorer.Application で非表示に呼び出す
```

DataSpider のトリガーを叩いていると読み取れる。**Web 版では IE を使えないため再設計が必要**（§18 C-5）。

### 8.6 後続処理

| 処理 | ストアド | 内容 |
|---|---|---|
| 支給包装材の納期更新 | `usp_shanghai_invoice_shikyu_hosozai_nouki_update` | 購買発注データの支給包装材の納入期日を、INVOICEヘッダの配送予定日で更新する |
| 巻芯入出庫情報の更新 | `usp_poem_makishin_nyu_syukko_update` | **別データベース（POEM）を更新する**（保守マップ §5.1） |

### 8.7 完了処理

- 「登録完了しました。」を表示
- 元INV_NO 選択時の処理（§6.2）を再実行して画面を更新する

明細のコンテナ番号を一括で更新する。

### 9.1 入力チェック

| 条件 | メッセージ |
|---|---|

### 9.2 処理

## 10. 「配送手配書」ボタン

### 10.1 入力チェック

| 順 | 条件 | メッセージ |
|---:|---|---|
| 1 | 元INV_NO が未入力 | INVOICE NOを入力してください。 |
| 2 | 担当が上海（1）以外 | 処理権限がありません。（国内発注用） |

### 10.2 確認ダイアログ

> 配送タイプ、コンテナ区分、コンテナNOの入力は済んでいますか。

「いいえ」を選んだ場合は中断する。

### 10.3 印刷用データの作成

1. 自分のログインコードの `tbl_t_shanghai_haiso_tehai_print_temp` を削除
2. `View_shanghai_haiso_tehai_pickup` から対象 INVOICE の明細を取得
   - 並び順：配送予定日 → 配送タイプ → コンテナ区分 → コンテナNO → INVOICE_NO
3. **配送パターンでグループ化**し、1 パターンにつき 1 行を印刷用一時テーブルへ登録する

**集計の内容**

| 項目 | 内容 |
|---|---|
| `invoice_no` | 枝番をカンマで連結（例：`SJ-TJ7699A,E`） |
| `total_carton` | グループ内のカートン数の合計 |
| `total_quantity` | グループ内の数量の合計 |
| `haisyo_yotei_ymd` | 配送予定日。**未入力のときは実行日**（§18 C-2） |
| `week_day` | 配送予定日の曜日 |
| `haiso_saki1` / `2` / `3` | 配送先。ビューから取得する |

### 10.4 出力する帳票

配送タイプごとに繰り返し、条件に応じた様式を選ぶ。

| 様式 | 条件 | 絞り込み |
|---|---|---|
| `R_上海輸入_配送手配_AIR` | 配送タイプ名が **`AIR` で始まる** | `haiso_type >= 10` |
| `R_上海輸入_配送手配_定期便3` | 配送先が **3 箇所**（`haiso_saki3` あり） | `haiso_saki3` が NULL でなく 0 でない |
| `R_上海輸入_配送手配_定期便2` | 配送先が **2 箇所**（`haiso_saki2` あり） | `haiso_saki2` あり かつ `haiso_saki3` なし |
| `R_上海輸入_配送手配_定期便` | 配送先が **1 箇所** | `haiso_saki2` も `haiso_saki3` もなし |

**配送先の数は利用者が指定するのではなく、ビューが返す値で自動的に決まる。**

### 10.5 入荷スケジュールの同時出力

配送タイプの**3 番目（配送タイプ＝3）が存在する場合のみ**、続けて発行する。

| 様式 | 絞り込み |
|---|---|
| `R_上海輸入_日新入荷` | `haiso_type = 3` |

**専用のボタンは無い。**配送手配書の発行に付随して自動で出力される。

### 10.6 進捗状況の更新

| タイミング | 処理NO |
|---|---|
| 配送手配書の発行時 | **7** |
| 入荷スケジュールを出力したとき | **12** |

### 10.7 配送タイプと様式の対応（2026-10-19 確定）

配送先は利用者が指定するものではなく、**配送タイプに紐づいた固定値**である。
`View_shanghai_haiso_tehai_pickup` が `View__haiso_type` を外部結合し、
`haiso_saki1` / `haiso_saki2` / `haiso_saki3` を取得している。

元データは項目マスタ `HKB`（`contents2` 〜 `contents4` が配送先コード）。

**配送タイプを選んだ時点で様式が決まる。**

| 様式 | 配送先 | 該当する配送タイプ（`haiso_type`） | 件数 |
|---|---|---|---:|

### 10.8 現行実装の問題点（2026-10-19 発見。Web 版では踏襲しない）

**① AIR の絞り込み条件が実データと合っていない**

```vb
DoCmd.OpenReport "R_上海輸入_配送手配_AIR", ... , "[haiso_type] >= 10"
```

AIR は 20〜28 であり、`>= 10` には **11〜19・29〜32・91〜105 の非 AIR も含まれる**。
AIR の配送手配書に定期便の明細が混入する条件が成立している。

コメントアウトされた旧コードは `If intTblHaisoType(n) >= 20` であり、
**名称判定へ変更した際にレポート側の絞り込みを直し忘れた**と見られる。

**Web 版では配送タイプを明示的に指定して絞り込む。**

**② 配送タイプが混在すると帳票が重複・混在する**

定期便の絞り込みは配送先の有無だけで、**配送タイプを特定していない**。

```vb
"( [haiso_saki2] is null Or [haiso_saki2] = 0 ) AND ( [haiso_saki3] is null Or [haiso_saki3] = 0 )"
```

1 つの INVOICE に配送先 1 箇所の配送タイプが 2 種類あると、
ループが 2 回まわり**同一内容の帳票が 2 枚出力される**。
AIR も配送先 1 箇所のため、同じ条件に該当する。

**実運用で 1 つの INVOICE に複数の配送タイプが混在するかは未確認**（§18 C-10）。

**③ 配送タイプ 12「太田⇒ロジ午前」の配送先が 3 件**

名称は 2 箇所だが `haiso_saki3 = 13` が設定されており、**定期便3 の様式で出力される**。
配送先コード 13 が何を指すかも不明（§18 C-11）。

## 19. SVF 連携方式（2026-10-19 確定）

> **サーバー側の設定手順は `docs/04_SVF帳票連携_設定手順.md` を正本とする。**
> 本節は設計上の決定事項を記す。

### 19.1 結論

**ASP.NET が所定の形式のテキストファイルを作り、SVF サーバーの監視フォルダへ置く。**
SVF（Universal Connect/X）がそれを自動で拾い、様式に流し込んで PDF を出力する。

```text
ASP.NET（ATOM）
    ① DB から帳票データを取得
    ② 連携用テキストファイルを生成（§19.3）
    ③ SVF サーバーの監視フォルダへ配置
            ↓ Universal Connect/X が自動で検知
       様式ファイル（.xml）へ流し込み
            ↓
       PDF 出力
    ④ ASP.NET が PDF を取得してブラウザへ返す
```

**Java の中継プログラムも DataSpider も不要。**
ASP.NET 側はテキストファイルの生成と配置のみを実装する。

当初検討した Java 中継案（`tools/svf-poc`）は本方式の確定に伴い廃止した。

### 19.2 保有製品と稼働状況

| 製品 | バージョン | 用途 |
|---|---|---|
| SVFX-Designer | Ver. 9.2（2014/7/7） | 様式ファイル（`.xml`）の作成 |
| SVF for PDF | Ver. 9.2（2014/3/14） | PDF の生成 |
| Universal Connect/X | － | 監視フォルダの検知・ジョブ実行 |

SVF は **Web サーバーとは別筐体**に導入され、**他システムの帳票出力で本番稼働中**。
管理画面は SVF サーバー上の `localhost:44080`。登録済みジョブは **101 件**。

稼働実績があるため、対応 OS・Java バージョン・アクティベーションのリスクは解消済み。

### 19.3 連携ファイルの形式

稼働中の他システムが出力している実ファイルから判明した形式。

| 項目 | 値 |
|---|---|
| 文字コード | **Shift_JIS（CP932）**。SVF の「出力設定」が `MS932` であることを実機で確認済み |
| 改行 | **CRLF** |
| BOM | **なし** |
| 区切り | **タブ** |

```text
<start>
VrSetOutputPrinter=（出力先の論理プリンタ名）
VrSetUseReportDirector=1
VrSetDocName2=（ドキュメント名）
<end>
見出し行（タブ区切り）
データ行（タブ区切り）
```

- `<start>` 〜 `<end>` が制御部。**SVF の API 関数名 = 値**を記述する
- 制御部の直後が**見出し行**、以降が**データ行**。**列数は一致させる**
- 見出し行の名前が**そのまま様式のフィールド名**になる（§19.4.1）

ファイル名は `<接頭辞>_<キー>_<yyyyMMdd>_<HHmmss>.txt` の形。
**接頭辞でジョブが振り分けられる**（§19.4）。

### 19.4 ジョブの振り分け

Universal Connect/X の「ジョブ」が、**データファイル名のワイルドカード**で様式を振り分けている。

| Job ID | データファイル名 |
|---|---|
| JOB001 | `D:\SVFDATA\data\C01*.txt` |
| JOB002 | `D:\SVFDATA\data\L02*.txt` |
| JOB003 | `D:\SVFDATA\data\L01*.txt` |
| JOB_L01P | `D:\SVFDATA\PDF\SAGYOU\L01*.txt` |

ジョブの設定値（実機確認）

| 設定 | 値 | 意味 |
|---|---|---|
| スプールモード | 印刷する／環境設定に従う | いったん印刷処理を通す |
| PDF オプション | 無効 | **ジョブ側では PDF 化していない** |
| CSV データフォーマット | その他 | カンマ以外＝**タブ区切り** |
| データファイルエンコーディング | 空欄 | 環境設定の既定に従う |
| 外部プログラム起動 | 起動しない | 前後処理なし |
| 実行様式ファイル検索パス | 環境設定に従う | 様式の置き場所は共通 |

実機で確認できた主要な列は次のとおり。

| 列 | 例 | 意味 |
|---|---|---|
| データファイル名 | `D:\SVFDATA\PDF\SAGYOU\L01*.txt` | **監視対象。ワイルドカードでジョブを振り分ける** |
| 実行様式名 | `?伝票置換区分` / 様式のフルパス | **`?` 始まりはデータ項目の参照。フルパスで直接指定もできる** |
| 置換マスターファイル名 | `D:\SVFDATA\mstr\作業表.mst` | データ項目の値を様式名へ変換する表 |
| ファイル定義 | `定義L01作業票PDF.txt` | **見出し付きのサンプルデータファイルそのもの**。列の並びと名前を定義する |
| 出力先 | `PDF` | PDF 出力 |
| 文書分割 | ✓ | キー項目ごとに PDF を分ける |
| 出力ファイル名 | `?出荷伝票番号+_+%SYSTEMDATE%` | **データ項目とシステム変数で組み立てる。**フルパスを前置してもよい |

PDF オプションが無効であるため、**PDF 化は出力先の論理プリンタ定義側で行われている**（推測）。
ATOM 側は `VrSetOutputPrinter` に PDF 出力用の論理プリンタ名を指定するだけでよい見込み。

**ATOM は「実行様式名に様式のフルパスを直接指定」する形を採る。**置換マスターは使わない。

**ATOM 用に新しいフォルダを作る必要はない。**
未使用の接頭辞を決め、**様式の数だけジョブを追加**すれば足りる。
テスト用ジョブを「対象」チェック OFF で併存させる運用が既にあり、検証も同じ手順で行える。

### 19.4.1 ファイル定義

ジョブの「ファイル定義」には、**見出し行を持つサンプルデータファイル**を指定する。
SVF はこれを読んで、データの列と様式フィールドの対応を決める。

**見出し行の名前がそのまま様式のフィールド名になる。**

#### 配置の鉄則

**データファイル・ファイル定義・`schema.ini` の 3 つは同じフォルダに置く。**
ファイル定義はデータファイルと同じフォルダから探されるため、分けると `RC=[-4029]` になる。

ジョブの「ファイル定義」欄は**ファイル名だけ**を書く（パスを付けない）。

**様式ファイルは既存様式と同じフォルダに置き、「実行様式名」もファイル名だけ**にする。
新しいフォルダに置いてフルパスで指定すると `VrSetForm` が `RC=[-30]` で開けない
（「実行様式ファイル検索パス＝環境設定に従う」の検索パス外になるため。推測）。

#### schema.ini が必須

ファイル定義と**同じフォルダ**に `schema.ini` を置く。テキストドライバ用の列定義。

```ini
[定義AT00接続テスト.txt]
CSVDataFormat=other
CharacterSet=OEM
Col1="REF_NO" Char Width 20
Col2="MEMO" Char Width 40
Format=TABDELIMITED
MaxScanRows=10
SepHeadDetail=0
defencode=MS932
```

| キー | 意味 |
|---|---|
| セクション名 | **「ファイル定義」のファイル名。**データファイル名ではない |
| `Format` | `TABDELIMITED`（タブ区切り） |
| `CharacterSet` / `defencode` | `OEM` / `MS932`（CP932） |
| `Col<n>` | **見出し行と同じ名前を左から順に。**`Width` は最大長の目安 |

**セクション名がファイル定義のファイル名であるため、投入するデータのファイル名は毎回変わってよい。**

`schema.ini` は**フォルダに 1 つ**。既存の `D:\SVFDATA\data\schema.ini` は 63KB・30 セクション以上あり、
本番が共用している。追記を避けるため、**ATOM 専用の投入フォルダ `D:\SVFDATA\data_atom\` を設ける。**

既存の `schema.ini` のセクションは**すべて `[定義○○.txt]`**（ファイル定義のファイル名）であり、
データファイル名のセクションは 1 つも無い。**投入するデータのファイル名は毎回変わってよい。**

疎通確認用のサンプルは `tools/svf/定義AT00接続テスト.txt` と `tools/svf/schema.ini`（項目 2 つのみ）。

### 19.4.2 明細の持たせ方

稼働中の `定義L01作業票PDF.txt` では、**伝票単位の項目を明細行ごとに繰り返している。**

```text
伝票A / 明細1 / 配送先=X / 品目=…
伝票A / 明細2 / 配送先=X / 品目=…
伝票B / 明細1 / 配送先=Y / 品目=…
```

1 ファイルに複数伝票を入れ、**文書分割のキー**（`?出荷伝票番号` など）で PDF を分ける。

ATOM も同じ形を採る。

| 帳票 | 行数 |
|---|---|
| 配送手配書（定期便・定期便2・定期便3・AIR） | **1 伝票 1 行**（明細なし） |
| 日新入荷 | 同上 |
| 入荷明細書 | **明細ごとに 1 行。**ヘッダー項目は全行に同じ値を入れる |

### 19.4.3 値の書式

既存ファイルは固定長の名残で**スペース埋め・ゼロ埋め**されているが、
SVF 側で前後の空白は落ちていると見られる（推測）。
**ATOM はトリムした値をそのまま書く。**

| 項目 | 書式 |
|---|---|
| 日付 | 帳票に出す形（例 `2026/08/21`）。様式側で整形しない |
| 数値 | ゼロ埋めしない |
| 空欄 | 空文字（タブは詰めない） |
| 制御部の文字列 | **ダブルクォートで囲む**（例 `VrSetOutputPrinter="…"`） |

### 19.5 様式ファイル

- 形式は **XML 様式ファイル（`.xml`）**。SVFX-Designer で作成・編集する
- ファイル名は帳票名そのもの（例：`シンプルKO_購入依頼確認書.xml`、`海外発注書.xml`）
- 差し替えは `.bak` を残してファイルを置き換える手運用。**既存様式に影響しない**
- 2026 年に更新された様式が複数あり、**作成できる担当者が現存する**

**様式の作成は SVFX-Designer を操作する人の作業**であり、AI は実施できない。
現行の配送手配書 PDF を下地に起こす。既存様式を流用できるかは §18 C-16 で確認する。

### 19.7 ATOM 側の実装範囲

| # | 実装 | 配置 | 状況 |
|---|---|---|---|
| 1 | 帳票データの取得 SQL | `Atom.Data/Sql/`, `Atom.Data/Repositories/` | 未 |
| 2 | 連携ファイルの生成（CP932・CRLF・タブ区切り・BOM なし） | `Atom.Report/SvfDataFileWriter.vb` | **済** |
| 3 | 監視フォルダへの配置 | 同上 | **済** |
| 4 | 出力された PDF の取得とブラウザ応答 | `Atom.Web/Pages/Report/` | 未 |

`SvfDataFileWriter` は、書き込み途中のファイルを SVF に拾われないよう、
いったん `.writing` を付けた名前で書き出してから正しい名前へ変更する。
値に含まれるタブと改行は半角空白へ置き換える（列ずれ・行ずれを防ぐため）。

動作確認用に `Atom.Web/Pages/Report/SvfConnectionTest.aspx` を用意した。

本番の帳票画面ができたら削除してよい。

| 用途 | キー（案） |
|---|---|
| 監視フォルダのパス | `Svf.WatchFolderPath` |
| PDF 出力フォルダのパス | `Svf.PdfFolderPath` |
| 出力先論理プリンタ名 | `Svf.OutputPrinter` |
| ファイル名の接頭辞 | `Svf.FilePrefix.<帳票種別>` |

既存キー `Svf.FormFolderPath` / `Svf.WorkFolderPath` は本方式では使わないため整理する。

### 19.8 接頭辞とフォルダの案

既存の接頭辞（`C01` `CR1` `L01` `L02` `LR2` `P01…`）および
既存の PDF 出力フォルダ（`INVOICE` `PACKING` `KONPOU` `NOUHIN` `SEIKYU` `SAGYOU` ほか）と
**重ならないもの**を選ぶ。

| # | 帳票 | 帳票区分 | 接頭辞 |
|---:|---|---|---|
| 1 | 配送手配書（定期便） | `TEIKI1` | `AT01` |
| 2 | 配送手配書（定期便2） | `TEIKI2` | `AT02` |
| 3 | 配送手配書（定期便3） | `TEIKI3` | `AT03` |
| 4 | 配送手配書（AIR） | `AIR` | `AT04` |
| 5 | 日新入荷 | `NISSHIN` | `AT05` |
| 6 | 入荷明細書 | `NYUKA` | `AT06` |

PDF 出力先は **`ATOM` フォルダ 1 つ**にまとめ、ファイル名で区別する。

```text
?帳票区分+_+?REF_NO+_+?出力キー
```

| 列 | 内容 |
|---|---|
| `帳票区分` | `TEIKI1` など。**同じ REF_NO でも帳票ごとに別名**になる |
| `出力キー` | **ATOM が採番する `yyyyMMddHHmmss`。**同名衝突を防ぐ |

SVF の「出力設定」で**「出力ファイルの上書きを行う」が OFF** であることを実機で確認した。
同名 PDF が残っていると上書きされないため、**PDF 名は毎回ユニークにする必要がある。**
`%SYSTEMDATE%` は日付のみで衝突しうるので使わず、**ATOM が時刻まで含めた `出力キー` を渡す。**

ATOM は投入時に `出力キー` を控えておき、**その名前の PDF ができるのを待って取得する。**

### 19.11 旧 ATOM の帳票の出し方

旧 ATOM は **Access レポートの `acViewPreview`** で画面にプレビューを開くだけだった。
自動印刷もファイル保存もしていない。

```vb
DoCmd.OpenReport "R_上海輸入_配送手配_定期便", acViewPreview, , "…"
```

VBA 全 115 モジュールに `VrSet` / `SVF` の記述は 1 件も無く、**SVF は旧 ATOM では使っていない。**

Web 版はこれと等価な **「PDF をブラウザで開く」** とする。
**控えとしての PDF 保存は行わない**（旧版に無い機能のため）。
出力した PDF は役目を終えたら削除するか、次回出力で上書きされる扱いでよい。

### 19.10 待ち時間と画面の作り

| 項目 | 実測・設定 |
|---|---|
| 監視間隔 | **15 秒** |
| 処理時間 | 体感で即時 |
| 投入した txt | **消える**（SVF が消費する。ATOM が後始末する必要はない） |

**最悪で 15 秒強の待ちが発生する。**同期のポストバックで待たせると画面が固まるため、次の作りにする。

1. ATOM が `出力キー` を採番し、連携ファイルを投入する
2. **PDF の名前が確定している**ので、その名前のファイルができるのを**ポーリングで待つ**
3. できたらブラウザへ返す
4. 一定時間（30 〜 60 秒）出なければタイムアウトとしてエラー表示

**監視間隔は本番が共用する設定のため、ATOM の都合で短くしない。**

> 待ち方（ポストバックで待つ／別ウィンドウで進捗表示／非同期にしてあとから取得）は
> 実装時に決める。**要確認（C-23）**。

**まず項目 2 つ（`REF_NO` / `MEMO`）だけで疎通を確認する。**帳票レイアウトはその後。

1. ~~Web サーバーから投入フォルダへ**書き込めるか**~~ → **2026-10-19 確認済み。書き込める**
