## 1. 全体像

### 1.1 プロジェクトの役割

| プロジェクト | 役割 | 触るのはこんなとき |
|---|---|---|
| `Atom.Web` | 画面・共通レイアウト・認証の共通処理 | 画面の見た目、遷移、入力チェック |
| `Atom.Core` | エンティティ・業務ロジック・ログの抽象 | 項目の追加、業務ルール |
| `Atom.Data` | SQL の組み立てと実行 | 検索条件、登録・更新内容 |
| `Atom.Mail` | メール送信 | 通知メールの文面・宛先 |
| `Atom.Report` | SVF 帳票 | 帳票の出力 |
| `Atom.Tests` | 単体テスト | テストの追加 |

### 1.2 画面を開いたときの流れ

```text
ブラウザ
   ↓
Site.Master ……… 共通レイアウト（ヘッダー・メッセージ領域）
   ↓
BasePage ……… ログイン判定 → CSRF対策 → 権限判定
   ↓
各画面の .aspx.vb ……… イベント受付・値の詰め替え・結果表示
   ↓
Atom.Data の Repository ……… SQL の実行
   ↓
SQL Server
```

**認証・権限・ヘッダーは各画面に書きません。**すべて `BasePage` と `Site.Master` が面倒を見ます。

### 2.8 本登録の中身（`usp_shanghai_import_invoice_update`）

**DB 側のため変更できません。**挙動を知りたいときの参照先です（2026-09-25 にソースを確認）。

| 知りたいこと | 内容 |
|---|---|
| **担当区分（`@shanghai_chotatsu`）の用途** | **`boueki_flg` を決めるためだけ。**貿易(3)なら必ず 1。それ以外は PO の頭3文字が `NSN` / `HON` なら 1、違えば 0。**上海(1) と 調達(2) はこのストアドでは同じ動き** |
| 登録先 | `tbl_t_shanghai_invoice_meisai` / `tbl_t_shanghai_packing_meisai` / `tbl_t_shanghai_invoice_header_sub` の3つ |
| **PO の入り方** | `tajima_po_no` → `syanai_sansyo_no`、`tajima_po_no_original` → `syanai_sansyo_no_original` の**2列に入る** |
| **二重登録の防ぎ方** | 本テーブルに既にある INVOICE 番号を `LEFT JOIN ... WHERE pk_invoice_no IS NULL` で除外している。「追加」を選んでも同じ番号は二重に入らない |
| **登録対象の条件** | `tajima_po_no` と `suryo` が NOT NULL、品目コードがあること。**`err_status` は見ていない**ため、ストアド単体ではエラー行も登録される（画面側で止めている） |
| **箱数（`carton_qty`）の計算** | `SUM(carton_no_to - carton_no_from + 1)`。**引き算**なので C/NO は数値である前提 |
| **MISC / FREIGHT の読み替え** | 品目コードが空＋品名が `FREIGHT` → 品目コードを `MISC` に。品目コードが `MISC` ＋品名が空 → 品名を `FREIGHT` に。運賃行を通すための処理 |
| 固定値 | `del_flg`=0 / `nukitori_flg`=0 / `haiso_type`=0 / `container_type`=0 / `container_no`・`seal_no`=NULL |

## 6. 画面定義ファイル（AtomScreens.json）

場所: `src/Atom.Web/App_Data/AtomScreens.json`
**このファイルはアプリの再ビルドなしで反映されます**（更新を検知して読み直します）。

```json
{
  "DefaultHeaderBackColor": "#400080",
  "Blocks": [
    {
      "Title": "ブロックの見出し",
      "ColorName": "blue",
      "Column": 1,
      "Screens": [
        { "MenuNo": 101, "Title": "画面名", "Url": "", "HeaderBackColor": "" },
        { "MenuNo": 108, "Title": "他画面から開く画面", "Url": "", "HeaderBackColor": "", "Hidden": true }
      ]
    }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `DefaultHeaderBackColor` | ヘッダー背景色の既定値 |
| `Title`（ブロック） | メニューの見出し |
| `ColorName` | `blue` または `pink`。それ以外は `blue` 扱い |
| `Column` | 置く列。1〜3。それ以外は 1 扱い |
| `MenuNo` | メニュー番号。権限判定と遷移のキー |
| `Title`（画面） | メニューのボタン名／ヘッダーの画面名 |
| `Url` | 遷移先。**空なら未実装**（押すとメッセージ） |
| `HeaderBackColor` | その画面のヘッダー背景色。空なら既定値。`#RRGGBB` 以外は無視 |
| `Hidden` | `true` のとき**メニューに表示しない**。他の画面からのみ開く画面に使う。省略時は `false`。メニュー番号による遷移・権限判定・ヘッダーの画面名表示は通常どおり動く |

## 7. 新しい画面を作るときの手順

1. **画面設計書を受け取り**、`docs/specs/<menuNo>_<画面名>.md` に原文のまま保存する
2. 矛盾・不明点を「要確認事項」として質問し、回答を設計書末尾に追記する
3. `src/Atom.Web/Pages/<領域>/` に `.aspx` `.aspx.vb` `.aspx.designer.vb` を作る
   - 領域: `Master`（マスタ保守）/ `Entry`（入力）/ `Search`（照会）/ `Report`（帳票）/ `Common`（共通）
4. コードビハインドで `Inherits BasePage` とし、`OnInit` で `Me.MenuNo` を設定する
5. SQL は `src/Atom.Data/Sql/<エンティティ>Sql.vb`、実行は `src/Atom.Data/Repositories/<エンティティ>Repository.vb` に置く
6. エンティティは `src/Atom.Core/Entities/` に置く
7. `App_Data/AtomScreens.json` の該当 `MenuNo` に `Url` を設定する（これでメニューから開けるようになる）
8. ヘッダーへ画面固有ボタンを置くときは、`OnInit` で `Me.HeaderActions.Add(...)` する
9. `Atom.Web.vbproj` などに新しいファイルを登録する
10. `Web.config` の `Atom.SystemVersion` を上げる
11. **`docs/UT/ATOM_テスト仕様書.xlsx` にその画面のシートを追加する**
12. **本ファイル（保守マップ）の §2 逆引き表と §3 画面一覧を更新する**

## 9. このファイルの更新ルール

**実装を変更したら、同じ作業の中で本ファイルを更新します。**「あとでまとめて」はしません。

| 変更したもの | 更新する節 |
|---|---|
| 画面を追加・削除した | §3 画面一覧、§2 逆引き表にその画面の節、`docs/UT/` のテスト仕様書 |
| 共通処理のクラス・ファイルを追加した | §4 共通処理一覧 |
| `Web.config` の設定キーを増やした | §5 設定値 |
| `AtomScreens.json` の項目を増やした | §6 画面定義ファイル |
| 「〜を直したいときはここ」が変わった | §2 逆引き表 |
| 未対応事項が解消した／増えた | §8 未対応・注意事項 |

更新したら冒頭の**最終更新日**も直します。
